## Revisión por área

- **Fechas y horas.** API y SnapshotRepository usan medianoches consecutivas de Madrid, sin asumir días de 24 horas. Se añaden comprobaciones de 25 h el 25/10/2026, 23 h el 28/03/2027 y fin de año. La API compara instantes UTC; el motor usa minutos UTC y límites de inicio incluido/fin excluido. Se añade el test Dart de esos límites. `datos_hasta` en API/motor es el inicio del último turno publicado, no su final al día siguiente. Se conservan mensajes diferentes para antes de los datos, futuro y zona no publicada. Los tests previos de nocturnas, Murcia y fechas pasadas continúan pasando. No se extrapolan rotaciones.
- **Parsers.** Las suites existentes cubren los PDF de Baleares y BORM, transcripción de Sant Antoni, columnas/localidades, duplicado tras salto de página de Los Alcázares, CSV/PDF Madrid, correcciones entre descargas de Navarra, DBF/UTM y Zaragoza. Los siete tests nuevos de ingesta cubren minutos, medianoche, celdas incompletas y horas inválidas. CSV Madrid sigue usando UTF-8 con BOM; las codificaciones desconocidas no se «adivinan». Los JSON ilegibles de Navarra/Zaragoza generan aviso y se conserva lo legible. Una fila omitida puede producir extracción parcial: la validación de no vacío no demuestra completitud. Añadir umbrales/validación por fecha en el pipeline es parte de H09/H10, sin publicar automáticamente una extracción parcial como completa.
- **Aislamiento.** Cada importación es transaccional por fuente. Los datos de otras fuentes no se borran por un rechazo; una excepción posterior al upsert revierte la transacción. `actualizar_todo.py` tolera errores de descarga usando lo guardado; un fallo de parser/importador detiene los pasos siguientes, por lo que no publica esa ejecución. No se ha ejecutado el actualizador: incluso `--sin-descargas` puede geocodificar en red.
- **Geografía.** Se revisaron ámbito municipal con polígonos y huecos, respaldo por caja, distancia Haversine, deduplicación por farmacia/tipo/inicio y elección de cuadrante local. Las pruebas existentes de Madrid, Zaragoza y OSM siguen pasando. No se amplían ámbitos ni se aceptan coincidencias más laxas para obtener cobertura. No se verifica la posición real de cada farmacia contra servicios externos. Los centroides siguen etiquetados como aproximados.
- **Paridad.** Se revisaron motor, API, repositorios y fixture existente de paridad. Python comprueba mensajes y municipios; ejecutar la paridad app/API sigue bloqueado con el resto de Flutter. No se regeneró su fixture a partir del mismo código modificado para hacerlo pasar artificialmente. Diferencias pendientes: H15; además la API pagina mediante límite y el motor local devuelve toda su lista.
- **Pipeline (solo lectura).** El workflow no tiene `continue-on-error` ni `always()` en publicación; sus pasos dependen del éxito anterior. La falta de pruebas Flutter y validación de completitud siguen pendientes (H09/H10). No se modifican `.github/workflows/`, Pages ni scripts de actualización/exportación.
- **Privacidad y seguridad.** No se encontraron llamadas a logs/prints con coordenadas de usuario en el código de la app revisado; GPS no se guarda en preferencias y la búsqueda snapshot es local. Los GET de la API sí contienen ubicación en la URL: desplegar sin access logs y revisar logs de proxy sigue siendo parte de `docs/DESPLIEGUE.md`, requiere decisión de Alfonso. La búsqueda SQL usa SQLAlchemy con parámetros, sin interpolar las entradas de consultas en SQL. El escaneo de patrones de claves privadas, tokens GitHub, claves AWS y Google sobre archivos versionados no binarios no encontró coincidencias; no hay `.jks`, `.keystore`, `key.properties` o `.env` versionados. Es un escaneo acotado, no una garantía sobre historial o secretos de Actions.
- **App y textos.** Se revisaron errores de carga, timeout de GPS, permiso denegado, selección manual, recuperación del último lugar manual y fallback a instantánea incluida/cache. Se mantienen textos españoles. Las URLs de las fuentes y decisiones pendientes no cambian. La caducidad de Ahora y la accesibilidad quedan descritas con sus límites en H13/H14. Los documentos antiguos sobre Zaragoza pueden no reflejar sus descargas actuales: no se decide retirarla ni se cambian sus fuentes.
